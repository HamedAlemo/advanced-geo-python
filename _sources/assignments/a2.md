```{admonition} Why commit the lock file?
:class: tip
```

## Part 3: Undo Changes in a Git Repository (20 pts)

It might happen that you commit new changes to your git repository, and later you decide to undo them. There are two options for undoing your changes, namely `git revert` and `git reset`. In this exercise you will explore their differences, working inside your `assignment-2/` directory.

1. Navigate to the `assignment-2/` directory.
2. Create the following three files in the directory: `usage.md`, `cities.md`, and `notes.md`.
3. Add and commit each of the three files to your git repository **separately** (the first commit for `usage.md`, the second for `cities.md`, the third for `notes.md`). Use a commit message that indicates which file is being added.
4. Use `git log` to print the history of your commits. Note the ID associated with each commit.

Now try two things:

5. Use `git revert <ID>` to remove the changes associated with the commit that added `cities.md`. This command does not remove any changes committed *after* the commit ID you are using. Then inspect your files and run `git status` to see what changed. Run `git push origin` to update your GitHub repository.
6. Use `git reset <ID>` to remove **all** commits after a given commit ID cumulatively. Use it to remove all the commits you made *after* the commit that added `usage.md`. Inspect your files and run `git status` to see what changed.

```{note}
`git reset` rewrites history. After a reset, pushing may require care because your local history no longer matches the remote. Read the messages git prints, and if you are unsure, stop and ask in office hours rather than force-pushing.
```
